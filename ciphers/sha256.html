SHA-256

Secure (Modern)

A 256-bit digest for messages shorter than 264 bits — one-way, collision-resistant, and the verification engine of the digital world.

OriginNSA (designed); published by NIST as FIPS 180-2 in 2002
Year2002
TypeCryptographic hash function (Merkle-Damgård construction over the SHA-2 compression function) — not a cipher
StatusSecure; SHA-3 (Keccak) standardised 2015 as a structural alternative, not a replacement
Modern RoleCertificate signatures, software checksums, selected password KDFs, Bitcoin proof-of-work and selected signature schemes

Why This Matters

A cryptographic hash maps a variable-length message to a fixed-length digest. Different inputs must sometimes share a digest; collision resistance means that finding such a pair should be computationally infeasible. SHA-256 is widely used for checksums, signatures and Bitcoin proof-of-work. It has no decryption operation, but an attacker can still guess a low-entropy input and compare its digest. A bare hash also does not authenticate its sender.

Historical Context

NIST published SHA-1 in 1995 and FIPS 180-2 in August 2002, adding SHA-256, SHA-384 and SHA-512. SHA-224 was added in a 2004 change notice. The widely publicized MD5 collisions of 2004 and SHA-1 attacks from 2005 therefore came after this SHA-2 standardization. NIST later selected Keccak through a public competition; SHA-3 was standardized in 2015 as a structurally different family, not because full SHA-256 had been practically broken.

How It Works

The input is padded so its length is congruent to 448 mod 512, then a 64-bit length is appended. The padded message is split into 512-bit blocks. Each block is processed by the compression function, which mixes the block into a 256-bit internal state through 64 rounds of bitwise operations: rotations, XORs, AND/OR/NOT, modular addition, and round constants derived from the cube roots of the first 64 primes. After the last block the internal state is the hash output.

Two security goals are preimage resistance (finding an input for a specified digest) and collision resistance (finding any two distinct inputs with the same digest). Generic classical work factors for an ideal 256-bit hash are about 2256 and 2128 respectively. These are search-model estimates, not a guarantee that a guessable password takes that much work to recover.

Hash bytes, preserve field boundaries

The tuples ["ab", "c"] and ["a", "bc"] both become abc when their fields are simply joined. Both hash inputs are the same bytes, 61 62 63 in hexadecimal. Their equal digest is an encoding ambiguity, not a collision attack on SHA-256.

For this two-field teaching format, encode each field as its four-byte unsigned big-endian UTF-8 byte length followed by its UTF-8 bytes. A receiver checks each length and recovers exactly two fields, rejecting truncation or extra data. Lengths count bytes: é encodes as c3 a9, so its length is 2.

Security & Cryptanalysis

No practical collision attack is known against full SHA-256. Its Merkle–Damgård structure permits length extension: from H(secret ‖ data) and its length, an attacker can derive a digest for an extended message without learning the secret. Therefore that construction is not a safe message authentication code. Use an appropriate keyed construction such as HMAC-SHA-256; changing to an unkeyed SHA-3 hash does not itself provide authentication. Idealized Grover search reduces the generic preimage query exponent, but does not give an inexpensive real-world attack or settle every post-quantum application.

Where You Use It Today
WhereHow SHA-256 is Used
TLS / HTTPSSHA-256 is common; certificate signatures can use other approved hashes and signature algorithms
GitGit supports SHA-1 repositories and a SHA-256 object format; repository format determines the identifier
BitcoinProof-of-work searches for a double-SHA-256 digest, interpreted as an integer, below the current target
Password storageUsed in PBKDF2-HMAC-SHA256 and scrypt. Argon2 instead uses BLAKE2b internally; raw SHA-256 is unsuitable for password storage
Software integritysha256sum, package manager checksums, signed releases on every modern OS
Digital signaturesRSA-PSS and ECDSA can use SHA-256. Ed25519 uses SHA-512 as specified in RFC 8032
