# Three manual-cipher reconstructions

These are educational implementations, not tools for protecting messages.
Algorithmic code lives only in `js/ciphers/all-engines.js`; the exhibit renderer
consumes that code's traces. The bundles, workbench and embed configurations
use the same registered engines. Exhibit identities 165–167 are appended to
`data/exhibit-trust.json`, the existing collection source; old IDs stay fixed.

## Rasterschlüssel 44 — exhibit 165

Source: [Schlüsselanleitung zum Rasterschlüssel 44](https://cryptocellar.org/wmc/schluesselanleitung-zum-rs44.pdf),
**Ausgabe 27. März 1944**, including the second addendum's boundary/counting
clarification. The demo implements the original calculated readout, not the
18 October 1944 directly chosen readout column or emergency double transposition.

The original worked stencil has 24 rows × 25 columns, with ten white cells per
row (240 writing cells). Start at the indicated cell if white, otherwise the
next white cell in row order; wrap bottom-to-top. Determine readout by adding
the digits of the minute and body length and advancing physical columns from
the indicated beginning. Read numerical column ranks cyclically, each top-down,
skipping unused cells. A wrapped message can leave an unused gap in the middle.

The operating body length is **60–200** letters, reserving at least 40 cells.
The UI defaults to that limit. Explicit short teaching mode permits 0–59
without invented filler words; the 200 maximum always holds. Longer messages
were separate parts with separate message keys, not one enlarged stencil.
The pure API defaults to short teaching mode (`strict:false`). Coordinates
are zero-based in the API and one-based on the page. Default minute: 03.
Custom keys must have the same geometry and valid 1–25 rank permutation.

Independent known answers are transcribed from **printed pp. 12–15, Figs. 2
and 4 on pp. 18 and 20** (PDF pp. 20–23, 26, 28). The 77-letter example uses
time **1203**, row `ae` / column `bb` (API 4,13), digit sum 17, read rank 19.
The 64-letter example starts row `cc` / column `ac` (20,1), minute 21, digit
sum 13, read rank 12, and crosses the bottom boundary. Its printed ciphertext
group is `alege`, with one L; the scan was rechecked after an initial
transcription accidentally duplicated that letter.

The fixed default key is a factual transcription of the manual's figure,
not a generic random grid advertised as exact reconstruction. A separate reviewer reconstructed the 77-letter answer before the new engine
was written. The wrap answer was independently transcribed and checked against
a separate reference implementation during Phase 2, after the engine existed;
it was not generated by the production engine.
Tests also cover blocked/white beginnings, read-column wrap, 60/200 boundaries,
invalid stencils/permutations, normalization, state isolation and 250 property
trials over varying coordinates, minutes and valid lengths.

The UI expects **already prepared A–Z**. It does not implement German message
preparation, name alphabets, encoded indicators, key distribution, coordinate
reuse marks, emergency procedures or Wahlwörter. The convenience normalization
uppercases, removes accents, and discards other characters; it is not the
historical German formatter (umlaut expansion, CH/CK→Q, ß→SZ, spelled-out digits).

Historical attack evidence: [Captain W. J. Fried reports](https://cryptocellar.org/wmc/captain-w.j.fried-on-rs44.pdf),
F-79, 22 August 1944 (known-stencil message fitting), and F-93, 18 September
1944, pp. 1–2 (retransmission-based recovery, operator habits, cribs and sliding
masks). These conditional attacks justify the canonical Broken label; they do
not prove universal or prompt solution of every intercepted message.

RS44 cannot process a legitimate 100 KB body. Its scaling measurement therefore
uses valid 50/200-letter teaching inputs, batching until measurable CPU time.
It retains the production **10×** limit and complete registry coverage, and
separately tests rejection of oversized input. This bounded-domain measurement
is not an asymptotic claim about a hypothetical larger historical stencil.

## German Double Playfair — exhibit 166

Source: [Vorläufige Schlüsselanleitung zum Doppelkastenschlüssel](https://cryptocellar.org/wmc/schluesselanleitung-dk-1941.pdf),
**Ausgabe Dezember 1941**, printed pp. 3–6, §§4, 9–23 (NARA RG 457, Box 7,
Nr. 57). The chosen edition pairs rows of 17, then applies the documented
two-box substitution **twice**. Related 1940, Truppenschlüssel and
Nachrichtenschlüssel procedures are not silently substituted for this variant.

The daily squares contain each A–Z letter except J once. **§4 specifies J→II**,
two letters, not the generic Playfair J→I convention. Ciphertext J is invalid.
Full blocks have 34 letters; a final even block is split equally into shorter
rows, with no padding to 17. An odd plaintext receives a selected filler other
than X (default Z here). Decoding retains it; a real trailing Z cannot be
distinguished automatically. No escape scheme is introduced.

For encryption, locate pair first in A / second in B. Same-row positions move
right and cross squares; other positions take the crossed rectangle corners,
with B output first. Apply the rule again, still looking up first in A / second
in B. Decrypt looks up first in B / second in A, moves left for the same-row
case, and applies the inverse twice before reconstructing the two rows.

Independent known answers: original squares, `AA→VR→FY`, `FA→TR→VD`, and the
complete **54-letter** plaintext/ciphertext on printed pp. 4–6. The original
answer, including final groups on p. 6, is the test fixture's source. A separate
reviewer computed the answer independently before the new engine existed.
Property trials use 250 independently permuted square pairs; additional checks
cover odd/incomplete ciphertext, J expansion, invalid squares/fillers, retained
filler, incomplete final block, normalization and repeated execution.

The page enforces the **500-letter transmitted-body limit**. The pure engine
can explicitly omit that operational limit for 100 KB algorithm/complexity
testing (`strict:false`, its API default). Museum input convenience strips
accents, punctuation and digits; German abbreviations, umlaut expansion, number
words, operational headers, identification groups, key distribution and emergency
square generation are omitted and stated on the page.

[Ostwald and Weierud's research](https://cryptocellar.org/pubs/mcts.pdf)
(22 October 2021 author manuscript, published in *Cryptologia* 47(3), 2023)
provides historical comparison and cites Allied crib/statistical attacks.
Its modern hill-climbing experiments target **Truppenschlüssel**, not the
December 1941 two-stage procedure implemented here. This distinction is stated
on the exhibit.

## AMSCO — exhibit 167

Source: [American Cryptogram Association AMSCO specification](https://www.cryptogram.org/downloads/aca.info/ciphers/Amsco.pdf),
Cipher Exchange Guidelines, **printed p. 32**, complete worked example. The
sheet is undated; no invention date or military use is inferred from it.

Cells alternate one/two letters across the row **and down the first column**.
The starting cell can have one or two letters. The default is **two**, as in
the ACA example. This means row starts alternate even when the width is even;
alternating through a flattened cell list would implement a different rule.
The key is a genuine column-rank permutation (2–25 columns in this API/UI).
Multi-digit ranks are space-separated. Columns are extracted in ascending rank,
top-down. No nulls are added. Decryption reconstructs actual capacities from
ciphertext length, width and starting convention, including a final partial
digraph and missing cells in the final row.

Independent known answer: ACA's key **41325**, digraph first, complete
**57-letter** example. First row `IN|C|OM|P|LE`, second `T|EC|O|LU|M`, last
`A|PH|S`. Additional transparent hand checks for even width: key 12,
`ABCDEF`, digraph first → rows `AB|C / D|EF` → `ABDCEF`; single first →
`A|BC / DE|F` → `ADEBCF`. These are not answers generated by our engine.
Tests cover both conventions, every ragged ending across odd/even widths,
250 random permutations/messages, invalid keys, normalization, state isolation
and a correct 100 KB transformation.

The normalized domain is A–Z; uppercase, accent removal and nonletter deletion
are documented. Original punctuation is not recovered. Its statistical limits
are those of transposition; this page claims no named operational break for
which the ACA sheet offers no evidence.

## Reuse and independent evidence

The original manual facsimiles are curated by Frode Weierud at
[CryptoCellar](https://cryptocellar.org/wmc/index.html). Link to that collection;
do not rehost its scans, front matter, translations or third-party artwork.
The archive declares CC BY-NC-SA 4.0; the museum's code license is not substituted
for those source terms. ACA's sheet is credited and linked, not republished.
All displayed grids/squares are original DOM/CSS rendering of factual keys,
letters and cell geometry. No new third-party images are used. Prose is original;
expected vectors are limited functional transcriptions needed for validation.

Fixture strings and conventions are in
`tests/engines/helpers/historical-vectors.js`. Tests through the real exhibit
controls separately pin source answers, modes, animation stages and
valid→invalid→valid recovery. The source-file digests recorded in the task
evidence describe the downloaded research copies, not files committed here.
