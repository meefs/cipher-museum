Findings, ordered by severity:

1. **P2 — Artifact cards depend on an execution order the browser does not guarantee. Both PRs; inherited from main.** At `js/nav.js:160–164`, companion scripts are dynamically appended with `defer = true` but without disabling their default asynchronous execution or waiting for the data script. `js/artifact-cards.js:12–14` permanently returns when that data has not arrived. The new rendered-artifact assertion at `tests/test-trust-labels.js:184–186` explicitly evaluates data before renderer, so it bypasses the production loader.

   Ordinary desktop/mobile visits showed missing cards in 14 of 16 exhibit snapshots despite loaded data and no script errors. The deterministic reproduction delays only `artifact-cards-data.min.js` by 350 ms: Caesar on PR #1 and NEMA on PR #2 each have zero cards after network idle, with 143/147 data records present. Re-executing the renderer produces one card immediately. This is lost artifact content, including the newly centralized trust display, rather than a wrong classification in the data. The loader and early return are also present on the reviewed main base; this is an existing defect uncovered by the expressly requested artifact integration review. See [browser-followup.js](pr-review-2026-10-10/browser-followup.js) and [its results](pr-review-2026-10-10/browser-followup-results.json), the two `dependency order proof` records.

2. **P2 — The quadratic canary does not test the guard's rejection path or protect its 10× threshold. Introduced by PR #1; inherited by PR #2.** `tests/engines/scaling-canary.js:20–22` checks that a quadratic sample measures above ten; it never passes that sample through `run()` and expects rejection. The current production constant at `tests/engines/scaling.js:39` is correctly ten, and an independently injected, correctness-preserving quadratic Caesar implementation is rejected by the current guard. However, temporarily changing only that constant to twenty leaves the repository canary passing (exit 0), while the guard accepts the actual quadratic Caesar implementation at 16.1496×. The guard's console heading at `tests/engines/scaling.js:105` still prints a hardcoded “10x” after that mutation.

   This is a demonstrated regression-detector gap, not evidence of a current quadratic registered engine. Reproduce using [threshold-mutation.js](pr-review-2026-10-10/threshold-mutation.js); see [results](pr-review-2026-10-10/threshold-mutation-results.json) and [canary log](pr-review-2026-10-10/threshold-mutation-canary.log). The unmodified guard's independent rejection evidence is in [timing-review-results.json](pr-review-2026-10-10/timing-review-results.json).

3. **P2 — The four newly precached pages cannot load their artifact metadata on first use offline. PR #2.** `sw.js:21–46` precaches all four pages and the artifact renderer, but omits the renderer's required `js/artifact-cards-data.min.js`. `scripts/sw-version.js:7–14` hashes that bundle as an explicitly non-precached extra; hashing does not make it available offline.

   Start a fresh browser context, visit only `/index.html`, await the service worker's ready state and controller, disable networking, then open each new page. All four correct exhibit pages and all three interactive demos load, but all four have no artifact data or cards, and the data request fails. After visiting all four online first, requests succeed offline, yet three of four cards are still absent because of finding 1. The new offline pages thus extend an existing incomplete dependency policy. Their actual demos work; the defect concerns missing content, not total page failure. Fonts, lightbox, and the generic demo loader also fail requests on cold offline visits. See the `offline` records in [browser-results.json](pr-review-2026-10-10/browser-results.json) and the `offline-pr2-cold-*` screenshots.

4. **P3 — Two displayed classification statements remain independently maintained prose. PR #2.** `ciphers/nema.html:113` independently names its “Historical Only” classification; `ciphers/hagelin-c36.html:86` independently says the lineage carries “Broken.” Their current values agree with canonical data, but these statements are outside the generator's authority. Replacing only NEMA's prose classification with “Broken” leaves both `tests/test-trust-labels.js` and `tests/test-historical-exhibits.js` passing. This is a remaining centralization/coverage gap, rather than a currently incorrect header badge. See the two `wrong-prose-label` cases in [pr2-mutation-results.json](pr-review-2026-10-10/pr2-mutation-results.json).

5. **P3 — Myszkowski leaves a stale rank explanation after rejecting a keyword. PR #2.** The catch path at `js/historical-demos.js:104` clears the grid but leaves the caption populated by the previous valid key. With default `TOMATO`, clear the keyword: the status correctly says “Use a keyword of 2–24 letters,” output/grid are empty, but “Ranks: 4 3 2 1 4 3” remains. Reproduced at both viewport sizes; no incorrect ciphertext is produced. See [ui-followup-results.json](pr-review-2026-10-10/ui-followup-results.json).

Timing/calibration inspection found that batching uses the same repeat count for 25 KB and 100 KB round trips. CPU-time samples run serially, with a minimum 20 ms baseline, up to 128 repeats and the best of three samples. Every engine was measured. Independent quiet calibration measured a minimum positive CPU-clock step of 1 μs (6,462 zero steps in 10,000 immediate reads), safely below those batches. The largest observed ratio in that diagnostic run was **Stager 8.8033×** (33.318 → 293.307 CPU-ms, 16 repeats), below ten but with less margin than most engines. No current unreliable failure was reproduced in this environment. The earlier 25-of-40 coverage failure was not reproduced; the new logic batches fast engines and supplies valid special keys rather than excluding them.

An actual Caesar wrapper preserved plaintext/ciphertext behavior while performing quadratic work. The unmodified guard rejected it at 15.7× during `run()`; a separate measurement was 16.2310×. Batching therefore did not conceal that ordinary per-call quadratic regression. Finite sizes, representative keys, warmed repeated inputs and best-of sampling do not prove asymptotic complexity for every key or expose every cold/cached setup cost; GC and other process work can still affect margins. Cross-platform timing reliability was not certified. Finding 2 concerns protecting the guard itself against future weakening, not lowering its current bound.
